# VENIS · VERSION 1.3 LOCK

Estado: **BASE COMERCIAL DE PRODUCCIÓN**

## Principio
VENIS tiene mucha estructura detrás y muy poca fricción delante.

El operador debe poder:
1. elegir evento;
2. elegir una dirección visual;
3. completar datos;
4. generar;
5. compartir.

## Sistema interno
**TIPO DE EVENTO → RECETA → PLANTILLA → PALETA → TIPOGRAFÍA → DECORACIÓN → COMPONENTES → MOTOR → INVITACIÓN**

La receta es la unidad comercial: permite producir resultados coherentes sin diseñar cada invitación desde cero.

## Construido en 1.3
- 5 tipos de evento.
- 6 familias compositivas reales.
- 8 paletas.
- 5 sistemas tipográficos.
- 6 sistemas decorativos.
- Reglas por tipo de evento.
- Recomendación automática de estilo según evento.
- Ajuste fino sin romper el motor.
- Validación de contenido.
- Edición y reutilización de trabajos guardados.
- Nueva invitación desde cualquier pantalla.
- Publicación mediante enlace autónomo.
- WhatsApp, ubicación y compartir.
- Diseño responsive para móvil y escritorio.
- Compatibilidad con enlaces V1/V1.1.

## Regla comercial
No se agregan funciones por cantidad.

Cada nueva capacidad debe:
- aumentar la calidad percibida;
- reducir trabajo del operador;
- aumentar variedad sin duplicar código;
- mantener la experiencia inmediata.

## Limitaciones conocidas
- No hay backend.
- No hay cuentas ni autenticación.
- Los trabajos se guardan localmente en el dispositivo.
- La publicación se realiza dentro del hash de la URL.
- La portada usa una URL pública de imagen.

## Próxima frontera
La siguiente versión debe profundizar **activos e imagen, catálogo comercial, control de calidad visual y flujo de entrega**, no llenar la pantalla de opciones.

Esta versión queda congelada como base para empezar a vender y testear con clientes reales.
